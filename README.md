# Ellow Launchpad

Development foundation for Ellow Launchpad — a candidate career-launch platform (in future phases).

This is **Phase 1**: monorepo structure, a Next.js frontend, a FastAPI backend, PostgreSQL, Docker Compose, and the development workflow. No business features (auth, candidates, resumes, etc.) are implemented yet.

## Architecture

```
Browser → Next.js (apps/web) → FastAPI (apps/api) → PostgreSQL
```

## Repository layout

```
launchpad/
├── apps/
│   ├── web/     Next.js app (TypeScript, App Router)
│   └── api/     FastAPI app
├── packages/    Reserved for future shared packages
├── infra/       Reserved for future infrastructure/deployment config
├── docker-compose.yml
├── .env.example
└── Makefile
```

## 1. Prerequisites

- Docker and Docker Compose
- Node.js 20+ and npm (only needed for running the frontend outside Docker)
- Python 3.12+ (only needed for running the backend outside Docker)

## 2. Environment setup

Copy the example environment file and adjust values if needed (the defaults work out of the box for local development):

```bash
cp .env.example .env
```

## 3. Starting the application

```bash
make start
```

This builds and starts `web`, `api`, and `db` in the background. Equivalent to `docker compose up --build -d`.

## 4. Stopping the application

```bash
make stop
```

## 5. Running migrations

```bash
make migrate              # apply pending migrations
make migration name="add x table"   # generate a new migration
```

Alembic reads its database connection from `DATABASE_URL` (via application settings), so there are no hardcoded credentials.

## 6. Accessing the frontend

http://localhost:3000 — shows the Launchpad landing page with a live "Backend: Connected / Not Connected" status.

## 7. Accessing FastAPI

http://localhost:8000/health →

```json
{ "status": "ok" }
```

## 8. Accessing API documentation

http://localhost:8000/docs (Swagger UI, auto-generated by FastAPI)

## 9. Running tests

```bash
make test
```

Runs backend smoke tests (pytest) and frontend smoke tests (Vitest + React Testing Library). See [apps/api/README.md](apps/api/README.md) and [apps/web/README.md](apps/web/README.md) for running each suite individually.

## 10. Common development commands

| Command | Description |
|---|---|
| `make start` | Build and start web, api, and db |
| `make stop` | Stop all services |
| `make restart` | Stop then start |
| `make logs` | Tail logs for all services |
| `make logs-api` / `make logs-web` / `make logs-db` | Tail logs for one service |
| `make migrate` | Apply Alembic migrations |
| `make migration name="..."` | Generate a new Alembic migration |
| `make test` | Run backend + frontend tests |
| `make lint` | Lint backend (ruff) + frontend (ESLint) |

## Environment variables

See [.env.example](.env.example) for the full list with defaults:

- `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT` — PostgreSQL configuration
- `DATABASE_URL` — SQLAlchemy async connection string used by the API and Alembic
- `API_PORT` — host port the API is published on
- `WEB_PORT` — host port the web app is published on
- `NEXT_PUBLIC_API_URL` — API base URL used by the browser
- `API_INTERNAL_URL` — API base URL used by the Next.js server itself (the `api` Docker service name, not `localhost`)

PostgreSQL's port is intentionally not published to the host — only `web` and `api` are reachable outside the Docker network.
